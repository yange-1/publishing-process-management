# 出版流程项目管理平台 - 项目需求文档

## 1. 项目背景

目前单位出版业务中，每年约有200本图书进入出版流程。

一本书从编辑加工到最终出版，需要经历不同的校对流程，例如：

- 初审
- 一校
- 二校
- 三校
- 加校
- 核红

由于出版项目数量较多，且不同图书经历的流程节点存在差异，目前主要依靠人工沟通的方式了解项目进度。

实际工作中存在以下问题：

1. 无法快速查看一本书当前处于哪个流程阶段；
2. 无法直观看到全部出版项目的推进情况；
3. 编辑人员无法及时了解项目当前进展；
4. 校对管理人员无法及时发现长期停留在某一流程节点的项目；
5. 需要通过反复询问确认项目状态，增加沟通成本。

---

# 2. 项目目标

建设一个轻量化内部出版流程管理平台，实现：

- 出版项目统一管理；
- 出版流程节点可视化；
- 快速查看项目当前进度；
- 减少人工沟通和重复确认；
- 自动发现长期滞留项目；
- 为后续出版数据统计分析提供基础。

---

# 3. 第一阶段建设目标（MVP）

第一阶段不建设复杂企业级管理系统，而是建设一个简单、稳定、易使用的内部工具。

重点解决：

> “一本书现在进行到哪一步？哪些项目停滞？哪些项目需要关注？”

---

# 3.1 出版项目信息管理

每个出版项目包含以下基础信息：

- 书名；
- 责任编辑；
- 校对负责人；
- 当前阶段；
- 当前状态。

支持：

- 创建出版项目；
- 查看项目列表；
- 修改项目信息；
- 删除项目；
- 查看项目详细流程。

---

# 3.2 出版流程节点管理

不同图书根据实际出版情况选择需要经历的流程节点。

系统支持以下流程节点：

- 初审；
- 一校；
- 二校；
- 三校；
- 加校；
- 核红。

不同项目不要求经历全部流程。

例如：

- 部分项目只需要初审；
- 部分项目需要经历一校、二校；
- 部分项目可能直接进入核红；
- 部分项目需要完整经历多个校次流程。

系统根据项目实际情况展示对应流程。

每个流程节点，第一版即记录：

- 节点状态（未开始、进行中或已完成）；
- 开始时间；
- 完成时间。

通过流程记录，可以查看：

- 已完成节点；
- 当前进行节点；
- 后续待处理节点。

---

# 3.3 项目状态管理

项目状态包括：

- 未开始；
- 进行中；
- 已完成；
- 延期。

其中：

“延期”用于表示项目在当前流程节点停留时间过长，需要管理人员关注。

系统支持：

- 标记滞留项目；
- 在管理页面突出显示；
- 向校对管理人员提供提醒。

第一阶段不设置预计完成时间。

原因：

出版流程受作者修改、编辑调整、校样反馈等多种因素影响，预计完成时间可能造成不必要的管理压力和沟通矛盾。

---

# 3.4 出版流程可视化管理看板

为了方便校对管理人员快速掌握当前出版项目情况，系统首页采用可视化看板方式展示正在处理中的书稿。

## 3.4.1 项目展示方式

项目不采用单纯文字列表展示，而采用卡片式展示。

每个书稿项目以独立卡片形式显示：

包括：

- 稿件等级；
- 书名；
- 责任编辑；
- 校对负责人；
- 当前流程阶段；
- 当前状态；
- 收到书稿时间。

示例：

⭐⭐⭐《某某研究》

当前阶段：

二校

责任编辑：

XXX

校对负责人：

XXX

收到时间：

2026-08-01

状态：

进行中

---

## 3.4.2 流程节点颜色展示

不同出版流程阶段采用不同颜色进行区分。

第一阶段设置：

| 流程阶段 | 展示颜色 |
| -------- | -------- |
| 初审     | 蓝色     |
| 一校     | 绿色     |
| 二校     | 黄色     |
| 三校     | 橙色     |
| 加校     | 紫色     |
| 核红     | 红色     |

通过颜色区分，使管理人员能够快速判断当前项目分布情况。

---

## 3.4.3 稿件等级展示

根据出版工作实际情况，设置稿件重要程度。

第一阶段设置三个等级：

| 等级     | 展示方式 | 处理阈值 |
| -------- | -------- | -------- |
| 普通稿件 | 无星标识 | 30天     |
| 急稿     | ⭐⭐     | 15天     |
| 重要急稿 | ⭐⭐⭐   | 7天      |

急稿和重要急稿在页面中通过星级进行突出展示。

---

## 3.4.4 项目排序规则

首页项目按照优先级进行排序。

排序原则：

第一优先级：

稿件等级。

排序：

⭐⭐⭐重要急稿

↓

⭐⭐急稿

↓

普通稿件

第二优先级：

收到书稿时间。

同等级项目：

按照校对部门收到书稿时间排序。

收到时间越早的项目越靠前。

---

# 3.5 项目处理周期与滞留预警机制

## 3.5.1 计时起点

第一阶段项目处理时间从：

> 校对部门收到书稿时间

开始计算。

不以：

- 校对人员开始工作时间；
- 校对负责人分配时间；

作为主要计时依据。

原因：

管理人员需要关注的是：

> 书稿进入校对部门后是否长期未完成。

---

## 3.5.2 第一阶段阈值规则

根据稿件重要程度设置处理阈值。

普通稿件：

30天

急稿：

15天

重要急稿：

7天

初审阶段：

统一设置90天。

第一阶段暂不考虑：

- 不同字数；
- 不同图书类型；
- 更复杂业务规则。

后续根据实际运行数据逐步优化。

---

## 3.5.3 滞留项目展示

超过处理阈值的项目：

同时存在于两个区域：

第一：

正常项目时间序列中。

第二：

独立的“滞留预警区域”。

滞留区域采用醒目的红色展示。

显示内容：

- 书名；
- 稿件等级；
- 当前阶段；
- 已处理时间；
- 超出阈值时间。

示例：

⚠️ 滞留项目

⭐⭐⭐《某某研究》

当前阶段：

二校

已处理：15天

阈值：7天

超过：8天

# 3.6 数据统计扩展方向

---

# 4. 用户角色

## 4.1 编辑人员

主要需求：

- 查看自己负责的出版项目；
- 查看当前流程进度；
- 了解项目目前所处阶段。

---

## 4.2 校对管理人员

主要需求：

- 查看全部出版项目；
- 查看整体推进情况；
- 查看长期滞留项目；
- 根据提醒及时处理异常情况。

---

# 5. 使用规模

预计：

- 年项目数量：约200本；
- 年流程节点：约1000个左右；
- 使用人员：单位内部工作人员。

系统规模：

> 小型内部业务管理工具

---

# 6. 技术要求

第一阶段要求：

- 支持电脑浏览器访问；
- 操作简单；
- 界面清晰；
- 便于后续扩展。

当前技术方案：

前端：

- Next.js；
- React；
- TypeScript；
- Tailwind CSS。

开发辅助：

- Visual Studio Code；
- Claude Code AI 编程助手。

---

# 7. 项目开发原则

遵循：

1. 优先解决实际业务问题；
2. 第一阶段控制开发范围；
3. 保持系统简单稳定；
4. 为后续功能扩展保留空间；
5. 根据实际使用反馈持续优化。

---

# 8. 第一阶段交付成果

完成后预计包含：

- 出版项目列表页面；
- 项目创建与编辑功能；
- 出版流程展示；
- 流程节点状态管理；
- 流程开始时间和完成时间记录；
- 滞留项目提醒；
- 基础数据保存；
- 使用说明文档。

---

# 9. 后续扩展方向

在第一阶段基础上，可进一步增加：

## 9.1 出版数据统计

例如：

- 年度出版项目数量统计；
- 已完成项目数量统计；
- 进行中项目统计；
- 延期项目统计。

## 9.2 流程效率分析

例如：

- 各校次平均耗时统计；
- 不同流程节点耗时分析；
- 发现出版流程瓶颈。

## 9.3 工作量分析

例如：

- 不同责任编辑项目数量统计；
- 不同校对负责人工作量统计。

## 9.4 智能提醒

未来可扩展：

- 消息通知；
- 自动提醒；
- 异常项目预测。

## 项目定位

本项目第一阶段定位为出版流程管理工具。

通过对校对流程进行数字化管理，解决当前出版业务中的进度查询、流程追踪和滞留发现问题。

未来可根据业务发展，逐步扩展为出版业务数字化平台中的流程管理模块，并与其他出版业务系统进行数据对接。
