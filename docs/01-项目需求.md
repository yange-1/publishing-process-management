# 出版流程项目管理平台 - 项目需求文档

## 1. 项目背景

目前单位出版业务中，每年约有200本图书进入出版流程。

一本书从编辑加工到最终出版，需要经历不同的校对流程，例如：

- 初审
- 一校
- 二校
- 三校
- 加校
- 核红

由于出版项目数量较多，且不同图书经历的流程节点存在差异，目前主要依靠人工沟通的方式了解项目进度。

实际工作中存在以下问题：

1. 无法快速查看一本书当前处于哪个流程阶段；
2. 无法直观看到全部出版项目的推进情况；
3. 编辑人员无法及时了解项目当前进展；
4. 校对管理人员无法及时发现长期停留在某一流程节点的项目；
5. 需要通过反复询问确认项目状态，增加沟通成本。

---

# 2. 项目目标

建设一个轻量化内部出版流程管理平台，实现：

- 出版项目统一管理；
- 出版流程节点可视化；
- 快速查看项目当前进度；
- 减少人工沟通和重复确认；
- 自动发现长期滞留项目；
- 为后续出版数据统计分析提供基础。

---

# 3. 第一阶段建设目标（MVP）

第一阶段不建设复杂企业级管理系统，而是建设一个简单、稳定、易使用的内部工具。

重点解决：

> “一本书现在进行到哪一步？哪些项目停滞？哪些项目需要关注？”

---

# 3.1 来稿与任务发布

“来稿”不由校对主管填写。责任编辑在系统中发布一条校对任务，即代表该校次书稿已经进入校对部门。

责任编辑点击“发布校对任务”的时间，由系统自动作为：

- 本校次校对任务发布时间；
- 本校次来稿时间；
- 本校次滞留计时起点；
- 本校次进入书稿仓库的时间。

以上时间由系统自动生成，校对主管不重复录入。

责任编辑发布任务后，任务自动进入书稿仓库，状态自动变为“未开始”，校对负责人显示“待分派”，校对主管首页的书稿仓库数量自动增加，页面显示“新任务”提醒。第一版提醒采用系统页面内的数字、标记或醒目提示，不要求短信或邮件通知。

每一条校对任务的基础信息包括：书名、责任编辑、校对负责人、稿件等级、当前阶段、当前状态、来稿时间。

---

# 3.2 出版流程节点管理

不同图书根据实际出版情况选择需要经历的流程节点。

系统支持以下流程节点：

- 初审；
- 一校；
- 二校；
- 三校；
- 加校；
- 核红。

不同项目不要求经历全部流程。

例如：

- 部分项目只需要初审；
- 部分项目需要经历一校、二校；
- 部分项目可能直接进入核红；
- 部分项目需要完整经历多个校次流程。

系统根据项目实际情况展示对应流程。

每个流程节点，第一版即记录：

- 节点状态（未开始、进行中或已完成）；
- 开始时间；
- 完成时间。

通过流程记录，可以查看：

- 已完成节点；
- 当前进行节点；
- 后续待处理节点。

---

# 3.3 项目状态管理

项目状态包括：

- 未开始；
- 进行中；
- 已完成；
- 延期。

其中：

“延期”用于表示项目在当前流程节点停留时间过长，需要管理人员关注。

系统支持：

- 标记滞留项目；
- 在管理页面突出显示；
- 向校对管理人员提供提醒。

第一阶段不设置预计完成时间。

原因：

出版流程受作者修改、编辑调整、校样反馈等多种因素影响，预计完成时间可能造成不必要的管理压力和沟通矛盾。

---

# 3.4 出版流程可视化管理看板

为了方便校对管理人员快速掌握当前出版项目情况，系统首页采用可视化看板方式展示正在处理中的书稿。

## 3.4.1 项目展示方式

项目不采用单纯文字列表展示，而采用卡片式展示。

每个书稿项目以独立卡片形式显示：

包括：

- 稿件等级；
- 书名；
- 责任编辑；
- 校对负责人；
- 当前流程阶段；
- 当前状态；
- 来稿时间。

示例：

⭐⭐⭐《某某研究》

当前阶段：

二校

责任编辑：

XXX

校对负责人：

XXX

收到时间：

2026-08-01

状态：

进行中

---

## 3.4.2 流程节点颜色展示

不同出版流程阶段采用不同颜色进行区分。

第一阶段设置：

| 流程阶段 | 展示颜色 |
| -------- | -------- |
| 初审     | 蓝色     |
| 一校     | 绿色     |
| 二校     | 黄色     |
| 三校     | 橙色     |
| 加校     | 紫色     |
| 核红     | 红色     |

通过颜色区分，使管理人员能够快速判断当前项目分布情况。

---

## 3.4.3 稿件等级展示

根据出版工作实际情况，设置稿件重要程度。

第一阶段设置三个等级：

| 等级     | 展示方式 | 处理阈值 |
| -------- | -------- | -------- |
| 普通稿件 | 无星标识 | 30天     |
| 急稿     | ⭐⭐     | 15天     |
| 重要急稿 | ⭐⭐⭐   | 7天      |

急稿和重要急稿在页面中通过星级进行突出展示。

---

## 3.4.4 项目排序规则

首页项目按照优先级进行排序。

排序原则：

第一优先级：

稿件等级。

排序：

⭐⭐⭐重要急稿

↓

⭐⭐急稿

↓

普通稿件

第二优先级：

来稿时间。

同等级项目：

按照来稿时间排序。

收到时间越早的项目越靠前。

---

# 3.5 项目处理周期与滞留预警机制

## 3.5.1 计时起点

第一阶段项目处理时间从：

> 本校次来稿时间（即责任编辑发布任务时间，系统自动生成）

开始计算。

不以：

- 校对人员开始工作时间；
- 校对负责人分配时间；

作为主要计时依据。

原因：

管理人员需要关注的是：

> 书稿进入校对部门后是否长期未完成。

---

## 3.5.2 第一阶段阈值规则

根据稿件重要程度设置处理阈值。

普通稿件：

30天

急稿：

15天

重要急稿：

7天

初审阶段：

统一设置90天。

第一阶段暂不考虑：

- 不同字数；
- 不同图书类型；
- 更复杂业务规则。

后续根据实际运行数据逐步优化。

---

## 3.5.3 滞留项目展示

超过处理阈值的项目：

同时存在于两个区域：

第一：

正常项目时间序列中。

第二：

独立的“滞留预警区域”。

滞留区域采用醒目的红色展示。

显示内容：

- 书名；
- 稿件等级；
- 当前阶段；
- 已处理时间；
- 超出阈值时间。

示例：

⚠️ 滞留项目

⭐⭐⭐《某某研究》

当前阶段：

二校

已处理：15天

阈值：7天

超过：8天

# 4. 用户角色与任务责任链

系统采用“编辑发布、主管分发、校对结束”的责任链。

## 4.1 责任编辑（任务发布人）

每一条校对任务的发起人是该书稿的责任编辑。责任编辑负责：

- 在系统中发布本校次校对任务；
- 选择本次流程阶段；
- 填写或确认书名等任务信息；
- 查看自己负责书稿的当前状态；
- 搜索自己的书稿；
- 查看进入生产线时间；
- 查看完整校对历史。

正式使用时，编辑登录后默认只能查看自己作为责任编辑发布的任务。

## 4.2 校对主管（任务分发人）

校对主管从书稿仓库选择任务和空闲校对人员，执行“分发并开始”。该操作同时记录分发人、分发时间、被分发的校对人员、进入生产线时间和当前流程节点开始时间，并把任务从书稿仓库移入生产线、状态从“未开始”变为“进行中”、校对负责人从“待分派”变为具体校对人员。分发时间、进入生产线时间和流程节点开始时间在第一版为同一个系统时间点。

校对主管可以查看全部任务并分发。

## 4.3 校对人员（任务结束人）

当前具体校对人员完成本校次后点击“结束校对”。系统记录结束操作人、结束时间和本校次完成时间，本校次记录状态变为“已完成”。只能由当前任务对应的校对人员结束该任务，不能由无关校对人员结束。

结束后书稿退出生产线，该校对人员重新变为可分派状态，本校次历史记录永久保留。如果还有下一校次，由责任编辑再次发布新的校对任务，新任务重新进入书稿仓库并生成新的来稿时间。

## 4.4 一个校对人员一条任务

一个校对人员同一时段只能存在一条进行中的校对任务。校对主管分发时，系统检查该人员是否已有进行中任务；若已有则阻止再次分发，并显示其正在加工的书名与当前流程阶段，须等其结束当前任务后才能分发下一本。

## 4.5 权限范围

由于责任编辑、校对主管和校对人员分别发起不同操作，正式多人使用前，简单登录和角色权限不再是完全可选的远期功能，而是内部试用版的必要功能。演示版仍可使用虚构数据和静态角色展示。

## 4.6 操作责任记录

每一条校次任务至少保存：所属图书项目、流程阶段、任务发布人、任务发布时间、本校次来稿时间、稿件等级、当前状态、分发人、分发时间、校对负责人、进入生产线时间、结束操作人、本校次结束时间、是否滞留、流程顺序。其中发布人必须是责任编辑、分发人必须是校对主管、结束人必须是当前校对人员。已完成的历史记录不能被下一校次覆盖。

## 4.7 搜索结果

首页保留醒目的书稿搜索框。编辑搜索自己负责的书稿后，至少可以看到：书名、责任编辑、本校次任务发布时间、当前所在位置（书稿仓库、生产线、已返回编辑或全部完成）、当前流程阶段、是否进入生产线、进入生产线时间、当前校对负责人、是否滞留、查看校对历史入口。未进入生产线时显示“尚未进入生产线”。

## 4.8 校对历史时间线

书稿详情中的校对历史按时间顺序展示：责任编辑发布本校次任务 → 进入书稿仓库 → 校对主管分发任务 → 分发给哪位校对人员 → 进入生产线 → 校对人员结束任务 → 返回编辑 → 下一校次重新发布 → 是否发生过滞留。每个事件显示事件名称、操作人、操作时间和对应流程阶段。

## 4.9 总控预警

首页最多展示 20 条滞留任务，包含书稿仓库滞留和生产线滞留，每条显示所在区域；仓库中的普通稿即使排序靠后，只要滞留，也必须进入总控预警；超过 20 条时显示“查看全部滞留任务”。

## 4.10 未来统计数据

第一版不制作复杂统计页面，但上述操作记录必须真实保存。未来通过记录计算：每位编辑发布的任务数量、每个校次的来稿数量、书稿仓库等待时间、生产线加工时间、每位校对人员完成的任务数量、各校次平均耗时、滞留数量、不同流程节点的瓶颈。

# 5. 使用规模

预计：

- 年项目数量：约200本；
- 年流程节点：约1000个左右；
- 使用人员：单位内部工作人员。

系统规模：

> 小型内部业务管理工具

# 6. 技术要求

第一阶段要求：

- 支持电脑浏览器访问；
- 操作简单；
- 界面清晰；
- 便于后续扩展。

当前技术方案：

前端：

- Next.js；
- React；
- TypeScript；
- Tailwind CSS。

开发辅助：

- Visual Studio Code；
- Claude Code AI 编程助手。

---

# 7. 项目开发原则

遵循：

1. 优先解决实际业务问题；
2. 第一阶段控制开发范围；
3. 保持系统简单稳定；
4. 为后续功能扩展保留空间；
5. 根据实际使用反馈持续优化。

# 9. 后续扩展方向

在第一阶段基础上，可进一步增加：

## 9.1 出版数据统计

例如：

- 年度出版项目数量统计；
- 已完成项目数量统计；
- 进行中项目统计；
- 延期项目统计。

## 9.2 流程效率分析

例如：

- 各校次平均耗时统计；
- 不同流程节点耗时分析；
- 发现出版流程瓶颈。

## 9.3 工作量分析

例如：

- 不同责任编辑项目数量统计；
- 不同校对负责人工作量统计。

## 9.4 智能提醒

未来可扩展：

- 消息通知；
- 自动提醒；
- 异常项目预测。

## 项目定位

本项目第一阶段定位为出版流程管理工具。

通过对校对流程进行数字化管理，解决当前出版业务中的进度查询、流程追踪和滞留发现问题。

未来可根据业务发展，逐步扩展为出版业务数字化平台中的流程管理模块，并与其他出版业务系统进行数据对接。
