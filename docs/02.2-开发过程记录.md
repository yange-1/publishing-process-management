# 需求确认记录：确定编辑发布、主管分发和校对人员结束的任务责任链（旧方案，现已废止）

## 时间

2026年8月20日

## 确定方案

1. 来稿等于责任编辑发布任务：责任编辑在系统中发布一条校对任务，即代表该校次书稿进入校对部门。
2. 来稿时间由系统自动生成：任务发布时间、来稿时间、滞留计时起点、进入书稿仓库时间为同一个系统时间点。
3. 校对主管不录入来稿：来稿不由校对主管填写，来稿时间由系统自动生成，不重复录入。
4. 校对主管负责分发：从书稿仓库选择任务和空闲校对人员，执行“分发并开始”，记录分发人、分发时间、进入生产线时间和节点开始时间。
5. 校对人员负责结束：完成本校次后点击“结束校对”，记录结束操作人、结束时间和本校次完成时间。
6. 每一步保存操作人和时间：发布、分发、结束三个动作分别记录发起人和时间。
7. 新任务成为校对主管的页面提醒：发布后校对主管首页书稿仓库数量自动增加，页面显示“新任务”提醒。
8. 一个校对人员同一时段只能存在一条进行中的校对任务，已占用时阻止再次分发。
9. 下一校次由责任编辑重新发布新任务，新任务重新进入书稿仓库并生成新的来稿时间。

# 需求确认记录：确定四步极简流程、开放查看与自动责任记录

## 时间

2026年8月20日

## 确定方案

1. 四步极简流程：社内责任编辑“发布校对任务” → 外校公司主管一键“确认收稿” → 空闲校对人员一键“开始校对” → 当前校对人员一键“结束校对”。无分发、无领取登记、无返回责任编辑。
2. 来稿由系统生成：来稿 = 责任编辑发布任务，发布时间 = 来稿时间 = 滞留计时起点，由系统自动填写。
3. 外校公司主管不录入领取时间、不分发任务，仅一键确认收稿。
4. 校对人员自行开始：对“待开始”任务点击“开始校对”，系统自动设为校对负责人并记录开始时间；一名校对人员同一时段只能加工一本书。
5. 开放查看：所有登录用户可查看和搜索全部书稿，角色主要限制操作权限，不限制查看范围。
6. 状态统一：待确认收稿 / 待开始 / 进行中 / 已结束 / 已取消。
7. 自动填写：操作账号、操作人、所属公司、操作时间、状态、负责人、状态变化均由系统自动生成。
8. 事件只追加：TASK_PUBLISHED / RECEIPT_CONFIRMED / TASK_STARTED / TASK_COMPLETED / TASK_CANCELLED。
9. 数据对象：users / companies / books / tasks / task_events / audit_log；tasks 保留 cancelled_by、cancelled_at、cancellation_reason。
10. 社内校对主管为超级管理员，覆盖外校公司及其账号，代操作与纠错进入审计日志。
11. 取消：编辑可取消自己未开始的任务，超级管理员可纠错取消；取消记录取消人、时间、原因。
