# 出版流程项目管理平台 - 开发计划

## 1. 项目概述

### 1.1 项目名称

出版流程项目管理平台

### 1.2 项目目标

建设一个面向内部出版业务的小型项目管理平台，实现出版项目的信息统一管理、流程节点可视化展示以及项目进度跟踪。

通过系统替代目前依靠人工询问、微信群沟通等方式获取项目进度的工作模式，提高出版流程管理效率。

### 1.3 项目定位

本项目第一阶段定位为：

> 轻量化内部业务管理工具（MVP版本）

不追求复杂企业级项目管理功能，而优先解决当前出版流程中的核心管理问题。

后续根据实际使用情况逐步扩展。

# 2. 开发原则

项目开发遵循以下原则：

## 2.1 优先解决核心业务问题

第一阶段重点实现：

- 出版项目统一管理；
- 流程阶段展示；
- 当前状态查看；
- 滞留项目提醒。

暂不开发复杂功能：

- 企业级权限体系；
- 在线协同编辑；
- 复杂统计分析；
- 全流程数字出版系统。

---

## 2.2 保持系统简单稳定

系统面向内部工作人员使用，因此：

- 操作流程应简单；
- 页面信息应清晰；
- 减少学习成本；
- 保证数据安全。

---

## 2.3 保留未来扩展能力

系统设计时预留：

- 数据统计分析；
- 多用户权限管理；
- 移动端访问；
- 与出版社其他系统对接能力。

## 目标

## 工作内容

- 项目列表展示；

项目主要信息：

---

### 2. 任务发布功能

由责任编辑发布本校次校对任务（即“来稿”），系统自动生成来稿时间，任务进入书稿仓库。

录入或确认：

- 书名；
- 责任编辑（发布人）；
- 稿件等级；
- 本次流程阶段；
- 工作字数（本次校对任务字数，正整数；按每一次校对任务分别记录）。

---

### 3. 项目编辑功能

支持修改：

- 项目信息；
- 当前流程节点；
- 项目状态。

---

### 4. 取消任务功能

支持取消错误任务（不物理删除，保留历史）。

# 阶段三：出版流程管理功能（核心功能）

## 目标

实现出版流程节点可视化。

## 工作内容

建立出版流程节点模型：

包括：

- 初审；
- 一校；
- 二校；
- 三校；
- 加校。

（核红是「本次工作内容」之一，不是校次；工作内容为读校 / 核红 / 读校且核红。）

每个校次通过四个动作推进，分别由不同角色发起：

- 发布（社内责任编辑）：任务进入待确认收稿，状态为“待确认收稿”，生成来稿时间；
- 确认收稿（外校公司主管）：一键确认，状态变为“待开始”，记录确认人与确认时间；确认时页面显示工作字数，可修改外校确认字数（默认等于工作字数）后再确认；
- 开始（空闲校对人员）：一键开始，系统自动设为校对负责人，任务进入生产线，记录开始时间；
- 结束（当前校对人员）：一键结束，任务完成并退出生产线，记录结束时间。

---

## 流程特点设计

### 1. 支持不同流程

不是所有书稿必须经历全部流程。

例如：

普通图书：

```
初审 → 一校 → 二校 → 核红
```

简单项目：

```
初审
```

特殊项目：

```
一校 → 核红
```

系统支持根据实际情况选择流程节点。

---

### 2. 节点记录

每个节点记录：

- 是否完成；
- 开始时间；
- 完成时间。

---

### 3. 当前状态显示

系统显示：

- 当前完成节点；
- 当前进行节点；
- 下一工作节点。

# 阶段四：项目状态管理与提醒

## 目标

及时发现滞留项目。

## 工作内容

任务状态：

包括：

- 待确认收稿；
- 待开始；
- 进行中；
- 已结束；
- 已取消（超级管理员纠错）。

---

## 阈值管理

第一阶段采用简单阈值管理。

不同流程节点设置不同预警时间。

例如：

### 初审

默认：

90天

### 其他校次

普通稿：

30天

急稿：

15天

重要急稿：

7天

---

## 滞留提醒

当项目超过设定阈值：

系统标记：

“滞留”

并提醒：

- 校对管理人员；
- 项目负责人。

# 阶段七：系统扩展方向

未来可向数字化出版管理平台发展。

可能扩展：

## 1. 权限管理

角色（开放查看，角色限制操作）：

- 社内责任编辑：发布任务、取消自己未开始的任务、查看和搜索全部书稿；

正式多人使用前，简单登录和角色权限是内部试用版的必要功能，演示版可使用虚构数据和静态角色展示。
