# 校了么 —— 领导演示与交付清单

版本：V1.0
日期：2026年8月22日

---

## 1. 项目背景和要解决的问题

单位每年约有 200 本图书进入出版流程，一本书要经历初审、一校、二校、三校、加校等多个校对环节。目前主要靠人工询问、微信群沟通了解进度，存在：

1. 无法快速查看一本书当前处于哪个流程阶段；
2. 无法直观看到全部出版项目的推进情况；
3. 编辑人员难以及时了解项目进展；
4. 校对管理人员难以发现长期停留在某一节点的项目；
5. 反复询问确认状态，沟通成本高。

本平台通过把校对流程线上化，解决「一本书现在到哪一步、哪些项目停滞、哪些需要关注」的核心问题。

---

## 2. 当前平台已经完成的核心价值

- 出版任务统一管理（发布、确认收稿、开始、结束四步闭环）；
- 返稿配送与确认收货（运送中 / 送达 / 确认收货）；
- 流程节点与状态可视化（书稿仓库、生产线、已完成、总控预警）；
- 快速查看项目进度与完整校对历史；
- 自动发现长期滞留项目并红色预警；
- 四类角色（责任编辑、外校主管、校对人员、Dominance）权限清晰、操作极简；
- 平台品牌名统一为「校了么」；
- 数据本地可靠保存，支持备份与恢复验证。

## 3. 三分钟演示路线

**第一步：责任编辑发布虚构校对任务**
用责任编辑账号发布一条虚构书稿《测试图书A》（初审·急稿），说明「来稿时间由系统自动生成」。

**第二步：外校主管在首页确认收稿**
切换到外校主管账号，在首页「待确认收稿」区域点一次「确认收稿」（页面显示工作字数，可修改外校确认字数后再确认），书稿进入书稿仓库。

**第三步：校对人员开始和结束校对**
切换到校对人员账号，在书稿仓库点「开始校对」，任务进入生产线；再点「结束校对」，任务进入已完成。

**第四步：责任编辑搜索并查看完整历史**
切换回责任编辑账号，搜索《测试图书A》，点「查看历史」，展示发布、确认、开始、结束的完整时间线。

**第五步：Dominance 查看全局状态、仓库、生产线和预警**
用 Dominance 账号展示全局统计卡、书稿仓库、生产线、总控预警，以及账号管理和审计记录。

**第六步：返稿配送与确认收货**
切换回外校主管账号，在「运送中」列表对已结束校对的稿件点「送达」；切换回对应责任编辑账号，在首页「已“出餐”」中看到「已送达！请尽快确认“收货”～」，点「确认“收货”」后稿件立即从首页消失。

## 4. 演示时需要准备的虚构数据类型

以下均为虚构数据（书名、人员均为演示用）：

1. 一条「待确认收稿」任务；
2. 一条「待开始」任务（书稿仓库）；
3. 一条「进行中」任务（生产线）；
4. 一条「已完成」任务；
5. 一条「急稿」（二星）；
6. 一条「重要急稿」（三星）；
7. 一条「滞留任务」（超过阈值，用于展示红色预警）；
8. 一本包含多个校次历史的书稿（例如已完成一校、二校）。
9. 若干带「工作字数」「外校确认字数」的虚构任务（演示按每一次校对任务分别记录字数，暂不计算费用）。

注意：滞留任务需临时把「来稿时间」改早到超过阈值，属演示用虚构数据。

已提供演示数据库生成命令：`npm run db:demo`，生成到 `data/demo/publishing-process-demo.db`（全部虚构演示数据）。演示账户（密码统一 123456，仅演示用）：demo_admin（演示管理员 / Dominance）、demo_editor_a / demo_editor_b（演示编辑甲 / 乙）、demo_supervisor（演示主管甲，外校公司A）、demo_proofreader_a / demo_proofreader_b（演示校对甲 / 乙，外校公司A）、demo_supervisor_b（演示主管乙，外校公司B）、demo_proofreader_c（演示校对丙，外校公司B）。

## 5. 演示前检查清单

- 平台能正常启动、页面能打开；
- 已准备四个角色的演示账号，密码可正常登录；
- 已准备上述虚构演示数据；
- 首页统计卡、仓库、生产线、已完成、预警各区域数据正确；
- 搜索、筛选、查看历史功能正常；
- 浏览器为演示用干净的电脑浏览器；
- 演示数据全部为虚构，不含真实未出版书名或敏感人员信息。

---

## 6. 演示过程中不应做的操作

- 不输入真实未出版书名、作者或稿件内容；
- 不演示账号管理中的真实人员信息；
- 不删除或清空数据库、备份文件；
- 不在公开网络环境演示真实数据；
- 不临时修改业务代码。

## 7. 「演示版已经完成」清单

- 四步业务闭环（发布→确认收稿→开始→结束）；
- 角色登录与权限区分（责任编辑/外校主管/校对人员/Dominance）；
- 书稿仓库、生产线、已完成、总控预警四类视图；
- 五张统计卡；
- 稿件星级与排序；
- 初审 90 天、其他 30/15/7 天滞留规则；
- 待确认收稿与书稿仓库正确分离；
- 校对人员一人一书、可从首页仓库或搜索结果开始；
- 外校主管首页直接确认、已完成独立页面；
- 责任编辑本人维度首页 + 部门仓库（按公司筛选与数量）；
- 责任编辑「我的待确认」范围修复（数量与列表只含本人发布的任务）；
- 任务字数（工作字数 + 外校确认字数，按每一次校对任务分别记录，暂不计算费用）；
- 搜索、任务筛选、书稿历史时间线；
- 取消任务（保留历史，不物理删除）；
- 统计报表中心（月报 / 半年报 / 年报；社内校对主管看全平台、外校主管仅看本公司；一个校次计 1 本次；平均50万字完成周期；预测版 / 实绩版）；
- 返稿配送（外校主管「运送中／送达」、Dominance「代送达」及审计、责任编辑「已“出餐”／确认“收货”」、已送达未确认按上海自然日最多显示 7 天）；
- 责任编辑书稿仓库按外校公司筛选联动显示「前方还有 x 份待制作」、生产线「“备餐”中，请耐心等待～」；
- 平台品牌名统一为「校了么」（登录页、首页顶部、浏览器标签）；
- SQLite 本地保存、备份与临时恢复验证。

## 8. 「同事正式使用前仍需完成」清单

演示版已完整可用，但要让单位内多位同事正式使用，还需完成：

1. **单位内网主机或服务器**：把系统部署到一台长期在线的内网机器；
2. **固定内部访问地址**：给同事一个固定的内部网址；
3. **生产模式运行**：以生产模式启动，而非开发模式；
4. **防火墙和访问范围**：只允许单位内网访问；
5. **自动启动和故障恢复**：机器重启后系统能自动启动；
6. **正式账号**：为每位同事创建正式账号并强制首次改密；
7. **独立备份位置**：把已验证的备份复制到移动硬盘/内网文件服务器等独立存储；
8. **小范围试运行**：先找一小批同事试用，确认无误后再推广。

---

## 9. 明确说明：平台运行不需要大模型 API

- 本平台的运行**不需要 DeepSeek、Claude 或任何大模型 API**；
- DeepSeek/Claude 只在**开发过程中**辅助编写代码和整理文档，不是系统运行的一部分；
- 即使以后大模型账号或 API 失效，已经完成的平台仍然可以正常登录和使用。
